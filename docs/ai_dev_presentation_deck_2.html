📦 Dimension 02 · 上下文深度解析

Context 不是無上限硬碟，而是「極其昂貴的動態 RAM」

Stateless Architecture of LLMs

搞懂模型「沒有持續記憶」的底層機制，你就掌握了控制 Credit 帳單與抑制幻覺的 80% 密碼！

🔁 每次「發送」背後的真實封包流

在 IDE 裡每一次按下 Enter，系統從來不是只送出你打的那句話！而是將整份包裝重新打包做全量運算：

[System Prompt] (角色規範與安全邊界)
+ [專案關聯引用檔] (被自動或手動 @ 的檔案)
+ [前 N 輪全部對話紀錄] (歷史生成的代碼與抱怨)
+ [當前使用者最新輸入]
= 整包重新計費運算（Total Input Tokens）
💡 LLM 每次都是「重新閱讀全書」，上下文越長，每回合基本開銷越重。

⚠️ Context 的兩大致命陷阱

1. Token 計費滾雪球效應 (Compounding)

第 1 輪對話只讀 2,000 Tokens；聊到第 15 輪時，因為背負整串歷史紀錄，單次請求可能飆破 60,000 Tokens！這就是為什麼聊越久，Credit 燃燒得呈幾何級數暴增。

2. 注意力稀釋 (Needle In A Haystack 迷失)

雖然 Claude 5.5 支援高達 1M Tokens 超長視窗，但塞入整包 `build/` 或 40 個不相關檔案時，模型對核心資安約束與型態定義的注意力會被嚴重稀釋，導致寫出看似有理的垃圾。

🎯 解法：手術刀原則。只傳 Interface 契約、及時開新對話（Reset Context）！
🧠 Dimension 03 · 思考預算解析

Reasoning Effort：讓模型脫口而出，還是深思熟慮？

Thinking Budget & Extended CoT

在輸出第一行程式碼之前，模型在「隱藏思考鏈」中所花費的 Token 與時間，就是 Reasoning Effort。

Low / Instant Effort 思考時間：0s · 0 Token

直覺反射式輸出 (Instant Generation)

模型接收到 Prompt 後直接根據機率分布輸出 Token，不進行前置推演與自我驗證。

執行時間軸：
即時輸出 Code (1~3s)
✅ 最適合：樣板代碼 (Boilerplate)、CRUD、寫 Mock 資料、正則表達式、單純格式轉換。
❌ 禁忌：拿來解並發競爭、資安邊界推導（因為根本沒想過就寫出來了）。
⚡ 速度最快，Credit 零無謂耗費
High Effort / Deep CoT 思考時間：10~45s · 隱形計費

自我推演與校準 (Extended Thinking)

在回答前，模型在隱藏視窗中自主展開「假設 ➔ 證偽 ➔ 邊界回溯 ➔ 修訂架構」的多步驟推導。

執行時間軸：
Thinking 推導 (30s)
輸出 (5s)
✅ 最適合：高難度排錯（OOM/Race Condition）、設計分散式架構、推演資安防禦網。
⚠️ 代價：隱藏的 Thinking Tokens 全數計入 Output 費用！寫個 POJO 開 High Effort 是純粹的燒錢。
💸 昂貴但致命精準：把預算留給真正的架構硬仗
